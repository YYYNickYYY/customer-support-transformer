## 2. 输入敏感性诊断：模型会粗粒度路由，但细粒度遵循不足

先冻结 `docs/input-sensitivity-protocol-v1.md` 与 `outputs/input-sensitivity-20261006-v1/plan.json`，再对9组22条固定探针各生成一次。
固定同一第五checkpoint、tokenizer、原greedy、CPU2线程、seed42、512上下文/320新token，不启用重复约束、不输入参考/业务资料。记录完整token/步骤/top5/EOS，模型权重不变、梯度None。
全文AI评审按冻结的任务标准判断，而不是按文本差异、关键词或概率自动打分。完整正文和原文证据见同目录replies.jsonl、assessments.json及assessment-summary.json。

| 探针 | 观察与固定门槛结果 |
| --- | --- |
| 退款政策/申请/进度 | 三者有对应方向，组通过；有无商户依据、是否重复索取编号仍是独立质量缺陷 |
| 取消/追踪/删除一个商品 | 取消、追踪对应；删除商品误写整单移除并套账单下载步骤，组未通过 |
| 否定取消、否定申请退款 | 两条都违反明确否定，0/2尊重否定；正文不同也不能当理解了not |
| 订单号/发票号仅换值，明确要求包含编号 | 四条全部模板化为Order/Invoice Number，0/4正确复制；发票两值生成正文/token完全相同 |
| 退款申请三种等义表达 | 第三种“申请步骤”变成“可退款情形”，组未通过；不是只因结尾截断而失败 |
| 订单状态三种等义表达 | 全文动作仍指查询状态，组通过；第三条开头updating order措辞不准但后续实际查状态，未机械按一个词判失败 |
| 完全相同输入控制 | token/正文/停止精确一致，运行重复性有效；不是新的能力成功样本 |

3条达320上限，其余19条EOS：政策G01-POLICY、否定退款G04-NEG、申请步骤改述G07-C达上限。否定违背和任务转向在截断前已形成，不能归因为上限才出现。
不同编号的发票回复虽然完全相同，首步top5概率记录不同；输入在数值计算上有影响，但没有表现为正确复制。不能说“所有问题都没进模型”，更不能凭这些trace指认某个注意力头坏了。
政策方向通过只表示粗粒度路由，不表示真实商户政策正确；复制失败的0/4只适用于这四条显式要求，不是全dev保留率。

## 3. 整体判断与下一步

可支持的结论：模型已经能利用部分主题信息选择模板，但限定条件（否定、部分商品、具体编号）及部分改述的任务保持较弱。低loss/流利客服话术不能替代条件遵循；重复约束解决字面机制不等于解决语义机制。
22条是合成机制探针，样本小、分组异质，另有重复控制；不汇成总体理解率，不估线上或sealed_test泛化，不证明数据/模型/学习率单一因果。

下一步候选任务应回答一个明确问题：**训练输入与目标是否支持这些条件能力？**
先用预登记统计检查现有训练目标的“具体编号→占位符替换”、否定是否指向相反操作、删除部分商品与整单操作、申请步骤与资格说明的配对一致性。只统计/审计，不先修改；不能只挑这22条附近支持猜想的样本。
若目标本就教错，才考虑单一数据一致性因素；若目标正确但模型仍失败，再以固定数据的训练优化/容量实验检验，不以又一轮话术替换代替机制问题。
学习率对照不是禁止：完成上述原因边界后，仍可固定数据、初始化和预算做η与η/2对照，以dev曲线和同一能力探针为观察量。本轮没有授权或启动这一训练。
