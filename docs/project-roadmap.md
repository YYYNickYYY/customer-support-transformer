# 项目总体路线与实验决策规则

截至2026-10-06。本文整理目标与现有逻辑，不启动训练，不修改模型、学习率、轮数、解码设置或活动数据。历史日志保留原貌；本轮事实以新冻结记录为准。

## 1. 最终目的和两条工作线

首要目标是自己实现小型 Decoder-only Transformer，学懂数据、注意力、反向传播、优化与自回归生成。客服数据用于提供真实的教学任务，并不意味着本项目要达到可上线客服能力。

学习线的验收：能说明输入与标签错位、回复监督、padding/因果mask、Block组成、梯度与优化、训练/评估差异；能做小样本过拟合、复现训练、检查生成失败，并用测试定位错误。理解失败也是学习成果，不必每轮都刷新客服分数。

质量线的验收：在固定证据与评分尺度下，生成回复是否正确理解诉求、给出有效下一步、通顺、不重复、不作无依据保证。模型约188万参数、词表4000、从零训练，不能据此期待通用语言能力、真实业务知识或后台执行能力。

两条线分别记录。例如解码策略、注意力可视化、不同mask的教学实验，不能与保证话术改写混在同一次客服因素实验中。

## 2. 当前完整链条

固定数据revision与模板组划分 → 冻结tokenizer及输入格式 → Dataset与batch契约 → 手写小模型 → train训练与dev loss → 固定dev问题生成 → 多维评分和配对复核 → 缺陷归因 → 预先登记单因素与验收条件 → 审阅并冻结改动 → 用户决定是否在VS Code启动下一轮。

上游数据/评价版本变化必须形成新版本，不能靠更新一张表改变历史事实。发现新缺陷后先回到归因与评价一致性，不必立刻开启下一次训练。

### 数据与模型契约

- train/dev/sealed_test按去实体占位符、统一大小写及空白后的instruction模板组隔离。tokenizer训练不使用封存测试集。固定ID及哈希防止问题随实验悄悄改变。
- 冻结tokenizer：`artifacts/tokenizer/bitext-bpe-v1`。词表4000；训练上下文512。输入使用冻结的角色模板，自回归input_ids和labels错开一位；只监督回复及保留的EOS，问题与padding标签为-100。
- batch按本批最长样本动态padding，同时提供attention_mask。因果mask阻止偷看后续token，padding mask排除补齐位置，两者作用不同。
- 模型：Embedding与位置编码 → 4个Block → 最终LayerNorm → 词表输出层。d_model128、4头、FFN512、Dropout0.1；实现与单元测试分别检查形状、mask、梯度和输出。
- 当前质量实验固定5轮、batch8、学习率0.0003、weight_decay0.01、grad_clip1、seed42。原第1次是3轮，第2次改变为5轮，其后依次改变训练目标话术版本。
- 生成使用冻结的greedy设置及最多320个新token。512是模型输入上下文，不是320的同义词；判断截断要读实际stop_reason与完整原文。

### 训练评估与生成评估

训练时按真实前缀预测下一个token，dev loss也是给定真实前缀的预测误差；生成时模型不断把自己的输出作为后续输入。前者下降不保证后者不重复、不错实体或不承诺结果。

实际run的配置、summary/metrics、checkpoint及其数据哈希才说明某轮用了什么。不能因为一个通用生成配置写着best.pt，就假定它指向最新模型；批量评估须核对实际checkpoint及manifest。表格不决定训练配置。

## 3. 目前证据支持什么

同135条为每个intent5条，原27与新增108分开报告。风险按v1.1，意图/帮助/通顺按v1.0。第四、第五重复已统一复核v1.0；第二、第三重复尚未同口径复核，不与新数字横比。

| 指标 | 第四次 | 第五次 | 可作的解释 |
| --- | ---: | ---: | --- |
| best dev loss | 1.102187 | 1.102930 | 略高；没有多种seed证据，不能宣称有显著退步 |
| 意图均分 | 1.8074 | 1.8074 | 总均分相同不意味着逐题无变化 |
| 帮助均分 | 1.2074 | 1.3259 | 本诊断集整体改善，但存在逐题退步 |
| 通顺均分 | 1.6815 | 1.6889 | 略有改善，不证明稳定提升 |
| 无依据风险条数 | 57 | 43 | 同口径减少14，不是线上风险率 |
| 重复条数（新复核） | 58 | 63 | 净增5：新增20、消失15、持续43、均无57 |

原27重复16→10，新108重复42→53，说明只看原27会漏掉扩大范围中的副作用。历史55→66及“新增24”记录是旧评分快照，不能继续用于当前决策。

结论：第五在帮助/风险上有收益，在重复上有代价，不能宣布整体优胜。第五未支配第四，即不是所有维度都不差且至少一项更好。更低风险也可能来自回避提供具体帮助，要逐条检查，不用一个未定义加权总分掩盖取舍。

评分是AI开发诊断。隐藏轮次标签不能消除已有上下文影响，不称严格盲评或独立客服专家验证。0风险不是安全认证，参考回复不是商户事实来源。

## 4. 用归因决定动作，而不是循环改话术

| 缺陷类型 | 需要的证据 | 合理下一步 |
| --- | --- | --- |
| 训练目标遗漏/接缝 | 固定抽样或全覆盖审查，明确原句、相邻句及改写前后 | 同类覆盖与整句完整性改写，保留正常意愿 |
| 模型生成重组/循环 | 原文与目标对照、精确检索、停止原因；检索0不证明纯模型原因 | 单独诊断生成，不自动删训练礼貌句 |
| 实体丢失/虚构 | 客户已有实体与生成对象逐项对齐 | 作为独立实体问题记录，不冒充重复改善 |
| 长度截断 | tokenizer长度、剩余上下文、stop_reason与结尾 | 单独长度实验，不混改训练目标 |
| 评价漂移 | 相同核心句在不同轮次评分不同 | 全配对同口径复核，另存快照，不覆盖历史 |
| 无商户事实或工具结果 | 回复声明了实际流程、权限或已执行状态，却无支持记录 | 承认证据边界；小模型不能凭训练获得执行权限 |

不同类别可以同现，但必须分别记录证据。第五新增重复出现在未修改目标的intent中，只能说明不属于这些目标的直接新接缝，不能证明全局训练干预与其毫无关联。

## 5. 下一次训练前的固定决策门槛

本节是下一轮的建议协议，不回溯修改已经完成的实验合格条件。确认采用后再冻结具体协议，不能看到结果后换标准。

1. 写一个可被否定的假设。例如“修正退款结果保证遗漏可减少同退款焦点风险，且不增加整体重复或牺牲帮助”。不要以“分数更高”代替具体机制。
2. 唯一因素写到实际文件与基准版本。保持模型、tokenizer、划分、轮数、学习率、seed、checkpoint选择规则和生成设置不变。事先决定比较第五，以及第四作为较低重复参照；不事后挑最好比较对象。
3. 在训练前审阅清单：所有批准片段及改后全文，实体、条件、有效步骤、正常服务意愿、语法和接缝；保留候选也核查相似边界。计数、哈希和重放仅是工程验收，不能代替语义验收。
4. 主指标固定为同一冻结退款焦点的结果保证条数及同135总体风险条数，二者不混成一个数。帮助、意图、通顺、重复、EOS/截断、实体缺陷为回归监测；必要新标签先定义并对基准模型同步评估。
5. 建议继续门槛：焦点风险减少且总体风险不增加；同135三项质量均分不下降、重复不增加；任何严重的新误导/实体错误需复核并明确解释。门槛是开发推进规则，不是统计显著性或生产安全标准。不得把低于门槛的结果包装为整体更好。
6. 报告整体、原27、新108、相关intent及配对改善/退步，完整保留全部输出，不只展示成功样本。loss独立报告，不用于抵消生成风险或重复。
7. 若目标改写已通过全文检查但生成仍重组保证或循环，停止继续扩大同类替换。下一步改为独立模型/生成诊断，不承诺再改几条数据就一定解决。新实验须重新指定一个因素，不能顺便改学习率、模型和长度。

每轮只改一个因素有利于解释，但单seed的小型实验仍不足以证明普遍因果。若确认候选有价值，再预登记重复seed验证成本和方式，不能把重跑直到满意当验证。

## 6. dev与sealed_test的边界

135条被反复检查和用于选下一轮，已成为开发诊断集，不再是独立泛化验证。新增108即使最初未看过，后来也已进入调参过程。不能不断扩大dev再声称新选择是独立测试。

保留完整dev loss作拟合与训练诊断；固定生成集作可比开发观察；sealed_test继续封存，不读取或挑样。最终方案、checkpoint选择规则、评分标准与报告方式固定后，另行获得用户授权进行一次最终评估。若再根据测试结果改方案，测试就成为开发数据，不能继续宣称独立最终评估。

客服质量之外的机制学习可以在非封存数据上独立进行，不必为上分无限循环训练。
