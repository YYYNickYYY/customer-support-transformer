# 第五次模型输入敏感性诊断：预登记v1

日期：2026-10-06。明确问题：同一模型原始greedy生成是否随**诉求、否定、标识**有意义地变化，并对等义改述保持任务稳定？不是逐条修回复，也不是学习率实验。

先冻结 `outputs/input-sensitivity-20261006-v1/plan.json`、代码、环境、模型/模板/tokenizer哈希，再运行。固定第五best.pt，CPU2线程、seed42、greedy、角色屏蔽、上下文512、新token320；原解码不启用4-token约束，无训练或优化器。只输入问题，无参考答案/业务工具。新问题为人工设计的英文机制探针，不是dev随机样本，不接触sealed_test。

## 固定范围：9组22次生成

- 退款诉求3条：只把query对象从政策改成申请/进度，其他订单上下文相同。
- 订单动作3条：相同订单号，只换取消/追踪/删除一个商品。
- 否定2组各2条：只在want to cancel / want to request a refund插入语法必要的do not；负例没有补写替代任务。正确响应应尊重不想操作，可澄清需求，不能继续提供被否定操作路径或宣称执行。
- 实体2组各2条：仅换订单号/发票号，其他字逐字相同；双方都明确要求回复包含该编号。因此本探针必须复制正确标识，不因自然客服回复通常不必复述而免责。
- 等义改述2组各3条：保持退款申请或订单状态主题和同一标识，只换表达。不是要求逐字回复一样，而是都回应同一正确任务。
- 同输入控制2条：完全相同问题，greedy输出token/正文/停止应完全相同，排除把随机漂移当输入效应。

各组具体问题、expected_action、接受/拒绝条件随plan冻结。不得看输出后删问题、改句子、加测试或更换编号。不用已知坏例挑参数。每条只生成一次；仅同一哈希下补缺，损坏文件报错且不覆盖。

## 判断规则

阅读全文，以客户动词、对象和否定约束为准。政策：解释或指向政策，不能以索取退款申请详情取代；申请：说明申请路径或索取相关必要信息；进度：提供状态查询路径/核查或相关必要标识澄清，不能只讲资格。取消、追踪和删除部分商品也分别判断，不因含order/refund词算正确。删除部分商品不能改为整单取消。

每条人工AI记录 action_match、negation_respected（适用时）、required_id_copied（适用时）、证据和原因。无适用项为null，不能当0。明确编号要求需包含该完整字符串且不得把另一编号当目标；只输出通用占位符判复制失败。外观字段按需要与实际值核查，不按单个数字出现自动成功。
每组通过须所有成员满足各自条件；改述组须全部任务正确，全部同样答错不算稳定成功。不同文本不证明理解，文本相同也可能都正确；用正确任务响应判主结论。停止截断单列，不把更多EOS或措辞不同当能力。

辅助保存每步token/top5/EOS信息，比较首步分布与输出一致性，**不把概率当业务正确性置信度**。同输入控制不一致则整批有效性失败；其余缺陷用于定位，不能推出某注意力头、训练样本或学习率的因果。

## 决策边界

22条小探针不能估总体泛化或心理意义的理解。若能区分任务但否定/复制失败，问题是条件遵循的特定能力，不应笼统说模型完全不看问题；若改述不稳，记录稳定性限制。诊断结果不自动授权改数据/训练/模型。只做收尾与下一步假设，不加规则把探针逐条修通。
