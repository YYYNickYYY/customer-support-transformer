## 两个判读问题与副作用

对每题greedy与4个候选的完整文本各记录意图/帮助/通顺0–2、重复/风险0–1及实体问题0–1，给引文和理由；风险v1.1，其他v1.0，实体仅旁注不混进总分。参考不是业务政策依据，无真实商户资料/执行工具。风险0不代表事实已验证。

先问是否回应动作、对象、关键限定，再问是否有可执行下一步或必要澄清。不因分数高、长文/编号步骤、文字变化就判断更好。风险及实体分别检查；同义模板近似但步骤范围相同须记录任务多样性不足。

**可用候选（本次工程验收）**：意图2、帮助2、通顺至少1、风险0、实体问题0，且没有严重重复导致无法推进。轻度重复可记录1但不自动否决；“严重重复”需引文说明，另存布尔字段。占位符不自动风险1；已有匿名订单号要保留，关键入口未填并阻碍下一步会影响帮助。允许合理首轮澄清，不要求单轮解决任务。

**第一候选更好**：逐项对greedy比较。主维度意图/帮助至少一个改善、另一个不降，风险/实体/严重重复不恶化、通顺不降，才标better。两主维度不改善或相互交换则标same_or_tradeoff；主维度退步则标worse（仍报告风险是否减少）。不将五项加权成总分。可用性另存，与更好不是同一个定义。

候选池有可用答案但第一名不可用＝可供检查器纠错的机会；第一名已可用时不能把候选池成功算筛选收益。四候选全部不可用要区分“全部任务错误”和“主题正确但帮助/风险/实体不合格”。人工选择作为oracle上界，不伪造自动检查器表现，筛选结果仍not_implemented/null。
