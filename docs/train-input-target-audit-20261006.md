## 对四种能力的证据

**具体编号复制：监督表示确有差距。** 全414条编号候选，目标原样保留全部被检出的编号为0；413条有Order/Invoice Number或ID占位符。8条复核都是发票主题，输入具体数字变为通用字段。例如14957的85632→`{{Invoice Number}}`、4787的00108→`{{Invoice Number}}`，前导零也不保留。主题大体仍是获取/查看发票，但不构成准确复制该输入编号的示范。不能说普通客服必须复述编号，因此不把414条一律判业务错误；也未找到规则内显式要求复制的训练行。此前诊断明确要求复制，属于当前数据未展示支持的更强契约，不宜直接按学习率问题处理。该扫描非完整NER，没有验证所有编号表达。

**否定操作：未找到直接拒绝的窄规则示范。** 宽筛2303条不等于2303条“不要执行”。8条复核分别是否定已有账户、停止使用且要求注销、无法换货、不会下单、注册失败、不会设置地址、不要这笔购买、不会联系人工；都不是“不想取消/申请退款”。528“don't want purchase”可合理取消，不能当作诊断中“do not want to cancel”的负例。四条无宽否定对照均是退款/取消正向求助。报告是缺少已检出的对照支持，不是证明全train不存在语义反向条件；612和26713的dont拼写已表明宽正则会漏检。保持预定规则，不因看到漏检临时补扫描。

**部分商品：样本存在明确、正确的任务范围监督。** 44条候选均change_order；固定8条中7条索取具体待删商品、1条1469给逐商品Remove/Delete步骤，0条改为整单取消。四条域对照主要是整单取消；104仅说无法负担，目标将取消列为选项，标为ambiguous，不能当明确取消正例。第五模型删一个商品却生成整单/发票路径，不能归因于“这8条目标都写错”；也不能用8/8推出全部44或整个train正确。保证话术与页面真实性不在本轮重新评分范围。

**退款申请步骤：固定样本没有证实申请→资格错配。** 八条词面候选阅读全文后实际为申请3、时长1、进度2、资格2。申请16597有准备凭证/联系客服/网站入口，16831有申请渠道和订单号/原因，16867索取购买信息；均非只有资格清单。6666/6688输入本就问in which cases，讲资格符合任务。不能把request单词或get_refund标签当真实任务。四条对照中有rebate申请、进度及两条资格，主题对应。有限样本不能证明训练集完全无错配，也未排除主题不平衡、模板捷径、截断或学习机制问题。

## 结论与下一步

暂不训练、改参数或扩展逐句改写。两类问题应拆开：编号复制和反向否定存在**未展示训练支持/表示契约差距**的证据；部分商品和申请步骤则已有正确监督样本，不能用同一个“数据清洗不足”解释全部失败。

下一步建议先预登记**训练分布内条件利用诊断**：冻结来自已正确配对训练文本的部分商品/整单、申请/资格问题，比较同一第五模型能否在原问题及等义表达中遵循任务；必要时另立遮蔽/打乱输入对照，检查是否主要依赖回复模板。编号和否定按覆盖问题另列，不要求它们与分布内任务达到同一基线。该诊断本轮没有实施，具体设计须另行冻结；只有明确机制后再选择第六次唯一因素。

本轮未检查token截断，全文正确不等于模型实际看见完整目标；未估计总体缺陷率或心理意义的理解，无质量总分。48条由已知先前上下文的AI判读，非独立盲评或多人一致性研究。部分目标残留保证、措辞或工具执行问题记录为旁注，不借本轮审计重写风险评分标准，不更新历史因素表。
